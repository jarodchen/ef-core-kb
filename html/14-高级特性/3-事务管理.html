事务基础概念 ​

ACID 特性 ​

事务(Transaction) 是数据库操作的原子工作单元,保证数据一致性。

ACID 特性:

A - Atomicity (原子性)
    事务中的所有操作要么全部成功,要么全部失败
    
C - Consistency (一致性)
    事务执行前后,数据库保持一致性状态
    
I - Isolation (隔离性)
    并发事务互不干扰
    
D - Durability (持久性)
    事务提交后,变更永久保存

EF Core 事务 API ​

事务接口层次 ​

csharp
IDbContextTransaction
├─ Commit() / CommitAsync()      // 提交事务
├─ Rollback() / RollbackAsync()  // 回滚事务
├─ Dispose()                     // 释放资源
└─ GetDbTransaction()            // 获取底层 DbTransaction

IsolationLevel 枚举:
├─ ReadUncommitted    // 读未提交(最低隔离)
├─ ReadCommitted      // 读已提交(SQL Server 默认)
├─ RepeatableRead     // 可重复读
├─ Serializable       // 串行化(最高隔离)
└─ Snapshot           // 快照隔离

显式事务管理 ​

基本用法 ​

csharp
// 方式 1: using 语句(推荐)
using var transaction = await context.Database.BeginTransactionAsync();

try
{
    context.Orders.Add(order);
    await context.SaveChangesAsync();
    
    orderItems.ForEach(item => context.OrderItems.Add(item));
    await context.SaveChangesAsync();
    
    // 所有操作成功,提交事务
    await transaction.CommitAsync();
}
catch
{
    // 发生异常,回滚事务
    await transaction.RollbackAsync();
    throw;
}

// 方式 2: try-catch-finally
DbTransaction transaction = null;
try
{
    transaction = await context.Database.BeginTransactionAsync();
    
    // 执行操作...
    
    await transaction.CommitAsync();
}
catch
{
    transaction?.Rollback();
    throw;
}
finally
{
    transaction?.Dispose();
}

隔离级别脏读不可重复读幻读性能适用场景

var connection = context1.Database.GetDbConnection();

    context1.Database.UseTransaction(transaction);
    context2.Database.UseTransaction(transaction);

    await context1.SaveChangesAsync();
    
    // 操作 context2
    context2.Inventory.Update(stock);
    await context2.SaveChangesAsync();
    
    await transaction.Commit();
}
catch
{
    await transaction.Rollback();
    throw;
}
finally
{
    await connection.CloseAsync();
}

csharp
// 使用 TransactionScope(需要 MSDTC 服务)
using var scope = new TransactionScope(
    TransactionScopeOption.Required,
    new TransactionOptions 
    { 
        IsolationLevel = IsolationLevel.ReadCommitted,
        Timeout = TimeSpan.FromMinutes(5)

    // 所有操作成功

场景 3: 保存点(Savepoint) ​

csharp
// SQL Server 2022+ / PostgreSQL 支持保存点
using var transaction = await context.Database.BeginTransactionAsync();

try
{
    // 第一步操作
    context.Orders.Add(order);
    await context.SaveChangesAsync();
    
    // 创建保存点
    await transaction.CreateSavepointAsync("AfterOrder");
    
    try
    {
        // 第二步操作(可能失败)
        context.Payments.Add(payment);
        await context.SaveChangesAsync();
        
        await transaction.CommitAsync();
    }
    catch
    {
        // 回滚到保存点,保留订单
        await transaction.RollbackToSavepointAsync("AfterOrder");
        
        // 记录失败日志,但订单仍然有效
        _logger.LogWarning("Payment failed for order {OrderId}", order.Id);
        
        await transaction.CommitAsync();  // 提交订单
    }
}
catch
{
    await transaction.RollbackAsync();
    throw;
}

场景 4: 重试策略 ​

csharp
public class ResilientTransaction
{
    private readonly AppDbContext _context;
    private readonly ILogger _logger;
    private const int MaxRetries = 3;
    
    public async Task ExecuteWithRetryAsync(Func<Task> operation)
    {
        var retryCount = 0;
        
        while (retryCount < MaxRetries)
        {
            using var transaction = await _context.Database.BeginTransactionAsync();
            
            try
            {
                await operation();
                
                await transaction.CommitAsync();
                
                _logger.LogInformation("Transaction succeeded on attempt {Attempt}", retryCount + 1);
                return;  // 成功,退出
            }
            catch (Exception ex) when (IsTransientError(ex))
            {
                retryCount++;
                
                if (retryCount >= MaxRetries)
                {
                    _logger.LogError(ex, "Transaction failed after {MaxRetries} attempts", MaxRetries);
                    throw;
                }
                
                _logger.LogWarning(ex, "Transient error, retrying... Attempt {Attempt}/{MaxRetries}", 
                    retryCount, MaxRetries);
                
                // 指数退避等待
                await Task.Delay(TimeSpan.FromSeconds(Math.Pow(2, retryCount)));
            }
            catch
            {
                await transaction.RollbackAsync();
                throw;  // 非临时错误,立即抛出
            }
        }
    }
    
    private bool IsTransientError(Exception ex)
    {
        // 检测临时错误(网络问题、死锁等)
        return ex is SqlException sqlEx && 
               (sqlEx.Number == 1205 ||  // 死锁
                sqlEx.Number == -2 ||    // 超时
                sqlEx.Number == 64);     // 连接中断
    }
}

// 使用
var transaction = new ResilientTransaction(context, logger);
await transaction.ExecuteWithRetryAsync(async () =>
{
    context.Orders.Add(order);
    await context.SaveChangesAsync();
});

场景 5: 批量操作事务 ​

csharp
public async Task BulkInsertAsync(List<Product> products)
{
    using var transaction = await context.Database.BeginTransactionAsync();
    
    try
    {
        // 分批插入,每批 1000 条
        var batchSize = 1000;
        var batches = products.Chunk(batchSize);
        
        foreach (var batch in batches)
        {
            context.Products.AddRange(batch);
            await context.SaveChangesAsync();
            
            // 清理 ChangeTracker,避免内存溢出
            context.ChangeTracker.Clear();
        }
        
        await transaction.CommitAsync();
    }
    catch
    {
        await transaction.RollbackAsync();
        throw;
    }
}

陷阱 4: 跨异步上下文丢失事务 ​

总结 ​

核心要点 ​

  1. 默认行为: SaveChanges() 自动使用事务
  2. 显式事务: 跨多个 SaveChanges() 保证原子性
  3. 隔离级别: ReadCommitted 适合大多数场景
  4. 资源管理: 始终使用 using 语句
  5. 异常处理: catch 中必须 Rollback

事务选择指南 ​

场景推荐方案原因
单个 SaveChanges默认事务简单高效
多个 SaveChanges显式事务保证原子性
跨 DbContext共享连接+事务跨上下文一致性
跨数据库TransactionScope分布式事务
高并发Snapshot 隔离减少锁竞争
金融交易Serializable最强一致性
批量操作分批+保存点容错能力强
