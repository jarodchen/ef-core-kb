继承映射(TPH/TPT/TPC) ​

概述 ​

继承映射(Inheritance Mapping)是 EF Core 中将面向对象继承关系映射到关系数据库的技术。EF Core 支持三种继承映射策略:

  1. TPH (Table-Per-Hierarchy): 所有类型共享一个表,使用鉴别器列区分
  2. TPT (Table-Per-Type): 每个类型独立表,通过外键关联
  3. TPC (Table-Per-Concrete-Type): 每个具体类型独立表,包含所有字段

TPH (Table-Per-Hierarchy) ​

概念 ​

TPH 是 EF Core 的默认策略,将整个继承层次结构映射到单个表中,使用鉴别器列(Discriminator Column)来区分不同的子类型。

数据库表: PaymentMethods
┌────┬──────────┬──────────────┬────────────────┬───────────┐
│ Id │ Type     │ CreditCardNo │ BankAccountNo  │ Amount    │
├────┼──────────┼──────────────┼────────────────┼───────────┤
│ 1  │ CC       │ 1234-5678    │ NULL           │ 100.00    │
│ 2  │ Bank     │ NULL         │ ACC-9876       │ 200.00    │
│ 3  │ CC       │ 8765-4321    │ NULL           │ 150.00    │
└────┴──────────┴──────────────┴────────────────┴───────────┘
                    ↑ 鉴别器列

示例: 支付方式系统 ​

定义实体 ​

csharp
// 基类
public abstract class PaymentMethod
{
    public int Id { get; set; }
    public string OwnerName { get; set; } = string.Empty;
    public decimal Amount { get; set; }
}

// 派生类 1: 信用卡
public class CreditCardPayment : PaymentMethod
{
    public string CardNumber { get; set; } = string.Empty;
    public string ExpiryDate { get; set; } = string.Empty;
    public string CVV { get; set; } = string.Empty;
}

// 派生类 2: 银行账户
public class BankTransferPayment : PaymentMethod
{
    public string BankName { get; set; } = string.Empty;
    public string AccountNumber { get; set; } = string.Empty;
    public string RoutingNumber { get; set; } = string.Empty;
}

// 派生类 3: 数字钱包
public class DigitalWalletPayment : PaymentMethod
{
    public string WalletProvider { get; set; } = string.Empty;
    public string WalletId { get; set; } = string.Empty;
}

配置(可选,EF Core 会自动配置) ​

csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<PaymentMethod>(entity =>
    {
        // 指定鉴别器列名
        entity.HasDiscriminator<string>("PaymentType")
            .HasValue<CreditCardPayment>("CC")
            .HasValue<BankTransferPayment>("Bank")
            .HasValue<DigitalWalletPayment>("Wallet");
        
        // 配置各属性
        entity.Property(p => p.OwnerName).IsRequired().HasMaxLength(200);
        entity.Property(p => p.Amount).HasColumnType("decimal(18,2)");
    });
}

csharp
// 添加不同类型的支付记录
context.PaymentMethods.Add(new CreditCardPayment
{
    OwnerName = "John Doe",
    Amount = 100m,
    CardNumber = "1234-5678-9012-3456",
    ExpiryDate = "12/25",
    CVV = "123"

context.PaymentMethods.Add(new BankTransferPayment
{
    OwnerName = "Jane Smith",
    Amount = 200m,
    BankName = "Chase Bank",
    AccountNumber = "ACC-9876",
    RoutingNumber = "RTN-123"

await context.SaveChangesAsync();

// 查询所有支付方式

    .OfType<CreditCardPayment>()
    .ToListAsync();

    .OfType<BankTransferPayment>()
    .Where(b => b.Amount > 150)
    .ToListAsync();

// 生成的 SQL:
// SELECT [Id], [OwnerName], [Amount], [CardNumber], [ExpiryDate], [CVV]

TPH 优缺点 ​

优点:

  • ✅ 性能最佳(单表查询,无 JOIN)
  • ✅ 简单直观
  • ✅ EF Core 默认支持

缺点:

  • ❌ 大量 NULL 值(未使用的列为 NULL)
  • ❌ 无法对子类字段添加 NOT NULL 约束
  • ❌ 表结构不够规范化

TPT (Table-Per-Type) ​

概念 ​

TPT 为继承层次中的每个类型创建独立的表,基类和派生类通过主键/外键关联。

数据库表: PaymentMethods (基类表)
┌────┬───────────┬────────┐
│ Id │ OwnerName │ Amount │
├────┼───────────┼────────┤
│ 1  │ John Doe  │ 100.00 │
│ 2  │ Jane Smith│ 200.00 │
└────┴───────────┴────────┘

数据库表: CreditCardPayments (派生类表)
┌────┬──────────────────┬────────────┬─────┐
│ Id │ CardNumber       │ ExpiryDate │ CVV │
├────┼──────────────────┼────────────┼─────┤
│ 1  │ 1234-5678-...    │ 12/25      │ 123 │
└────┴──────────────────┴────────────┴─────┘
     ↑ 外键引用 PaymentMethods.Id

数据库表: BankTransferPayments (派生类表)
┌────┬────────────┬───────────────┬─────────────┐
│ Id │ BankName   │ AccountNumber │ RoutingNumber│
├────┼────────────┼───────────────┼─────────────┤
│ 2  │ Chase Bank │ ACC-9876      │ RTN-123     │
└────┴────────────┴───────────────┴─────────────┘

配置 ​

csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 基类
    modelBuilder.Entity<PaymentMethod>(entity =>
    {
        entity.ToTable("PaymentMethods");
        entity.HasKey(p => p.Id);
    });
    
    // 派生类 1
    modelBuilder.Entity<CreditCardPayment>(entity =>
    {
        entity.ToTable("CreditCardPayments");
        entity.HasBaseType<PaymentMethod>(); // 关键: 指定基类
    });
    
    // 派生类 2
    modelBuilder.Entity<BankTransferPayment>(entity =>
    {
        entity.ToTable("BankTransferPayments");
        entity.HasBaseType<PaymentMethod>();
    });
    
    // 派生类 3
    modelBuilder.Entity<DigitalWalletPayment>(entity =>
    {
        entity.ToTable("DigitalWalletPayments");
        entity.HasBaseType<PaymentMethod>();
    });
}

TPT 优缺点 ​

优点:

  • ✅ 数据库规范化,无冗余
  • ✅ 可以对子类字段添加约束
  • ✅ 表结构清晰

缺点:

  • ❌ 性能较差(需要 JOIN)
  • ❌ 查询复杂度高
  • ❌ 多层继承时 JOIN 更多

TPC (Table-Per-Concrete-Type) ​

概念 ​

TPC 为每个具体(非抽象)类创建独立的表,每个表包含基类和子类的所有字段,没有共享的基类表。

数据库表: CreditCardPayments
┌────┬───────────┬────────┬──────────────────┬────────────┬─────┐
│ Id │ OwnerName │ Amount │ CardNumber       │ ExpiryDate │ CVV │
├────┼───────────┼────────┼──────────────────┼────────────┼─────┤
│ 1  │ John Doe  │ 100.00 │ 1234-5678-...    │ 12/25      │ 123 │
└────┴───────────┴────────┴──────────────────┴────────────┴─────┘

数据库表: BankTransferPayments
┌────┬───────────┬────────┬────────────┬───────────────┬─────────────┐
│ Id │ OwnerName │ Amount │ BankName   │ AccountNumber │ RoutingNumber│
├────┼───────────┼────────┼────────────┼───────────────┼─────────────┤
│ 2  │ Jane Smith│ 200.00 │ Chase Bank │ ACC-9876      │ RTN-123     │
└────┴───────────┴────────┴────────────┴───────────────┴─────────────┘

注意: 每个表都包含基类字段(OwnerName, Amount)

配置 ​

csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 基类标记为抽象,不创建表
    modelBuilder.Entity<PaymentMethod>()
        .ToTable(t => t.ExcludeFromMigrations()); // EF Core 8+
    
    // 派生类 1
    modelBuilder.Entity<CreditCardPayment>(entity =>
    {
        entity.ToTable("CreditCardPayments");
        entity.HasKey(p => p.Id);
        
        // 配置基类字段
        entity.Property(p => p.OwnerName).IsRequired();
        entity.Property(p => p.Amount).HasColumnType("decimal(18,2)");
    });
    
    // 派生类 2
    modelBuilder.Entity<BankTransferPayment>(entity =>
    {
        entity.ToTable("BankTransferPayments");
        entity.HasKey(p => p.Id);
        
        entity.Property(p => p.OwnerName).IsRequired();
        entity.Property(p => p.Amount).HasColumnType("decimal(18,2)");
    });
    
    // 派生类 3
    modelBuilder.Entity<DigitalWalletPayment>(entity =>
    {
        entity.ToTable("DigitalWalletPayments");
        entity.HasKey(p => p.Id);
        
        entity.Property(p => p.OwnerName).IsRequired();
        entity.Property(p => p.Amount).HasColumnType("decimal(18,2)");
    });
}

TPC 优缺点 ​

优点:

  • ✅ 查询性能好(单表查询)
  • ✅ 可以对所有字段添加约束
  • ✅ 表结构独立

缺点:

  • ❌ 基类字段重复(数据冗余)
  • ❌ 修改基类需要更新多个表
  • ❌ UNION 查询复杂

三种策略对比 ​

特性TPHTPTTPC
表数量1个N+1个(N=派生类数)N个
JOIN 操作❌ 不需要✅ 需要❌ 不需要(但UNION)
NULL 值⚠️ 大量NULL✅ 无NULL✅ 无NULL
数据冗余✅ 无冗余✅ 无冗余❌ 基类字段冗余
查询性能⭐⭐⭐ 最快⭐ 较慢⭐⭐ 中等
插入性能⭐⭐⭐ 最快⭐⭐ 中等⭐⭐ 中等
规范化程度⭐ 低⭐⭐⭐ 高⭐⭐ 中
扩展性⚠️ 加字段影响所有类型✅ 独立扩展⚠️ 需修改多个表
EF Core支持✅ 默认✅ 需配置✅ 需配置(EF Core 7+)

选择指南 ​

推荐使用 TPH 的场景 ​

✅ 大多数情况下的首选

  • 继承层次较浅(2-3层)
  • 子类字段差异不大
  • 性能要求高
  • 数据量不是特别大

public class SmsNotification : Notification { }
public class PushNotification : Notification { }

推荐使用 TPT 的场景 ​

✅ 需要严格数据完整性

// 抽象基类不会被实例化
public abstract class Shape
{
    public int Id { get; set; }
    public string Color { get; set; }

}

public class Circle : Shape

    public double Height { get; set; }
    
    public override double CalculateArea() => Width * Height;
}

// 配置

    .HasDiscriminator<string>("ShapeType")
    .HasValue<Circle>("Circle")
    .HasValue<Rectangle>("Rectangle");
