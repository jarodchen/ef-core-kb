什么是跟踪查询 ​

跟踪查询的工作原理 ​

默认情况下,EF Core 会跟踪所有查询到的实体:

csharp
// 跟踪查询（默认行为）
var product = await context.Products.FindAsync(1);

// EF Core 内部:
// 1. 从数据库读取数据
// 2. 创建 Product 对象
// 3. 保存原始值快照
// 4. 开始跟踪变化

product.Price = 99.99m; // 修改被跟踪

await context.SaveChangesAsync(); 
// UPDATE Products SET Price = 99.99 WHERE Id = 1

AsNoTracking 的作用 ​

基本用法 ​

csharp
// 无跟踪查询
var products = await context.Products
    .AsNoTracking()
    .Where(p => p.IsActive)
    .ToListAsync();

// EF Core 内部:
// 1. 从数据库读取数据
// 2. 创建 Product 对象
// 3. 不保存快照,不跟踪
// 4. 直接返回

// 尝试修改不会保存到数据库
var product = products.First();
product.Price = 99.99m;
await context.SaveChangesAsync(); 
// ❌ 不会执行 UPDATE

csharp

❌ 不应该使用 AsNoTracking ​

1. 需要修改实体 ​

csharp
// ❌ 错误
var product = await context.Products
    .AsNoTracking()
    .FirstOrDefaultAsync(p => p.Id == id);

product.Price = 99.99m;
await context.SaveChangesAsync(); 
// ❌ 不会保存!

// ✅ 正确
var product = await context.Products
    .FirstOrDefaultAsync(p => p.Id == id);

product.Price = 99.99m;
await context.SaveChangesAsync(); 
// ✅ 会保存

全局配置 ​

设置默认跟踪行为 ​

csharp
// Program.cs
builder.Services.AddDbContext<AppDbContext>(options =>
{
    options.UseSqlServer(connectionString);
    
    // 所有查询默认无跟踪
    options.UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking);
});

根据环境配置 ​

csharp
builder.Services.AddDbContext<AppDbContext>(options =>
{
    options.UseSqlServer(connectionString);
    
    if (environment.IsDevelopment())
    {
        // 开发环境: 默认跟踪（便于调试）
        options.UseQueryTrackingBehavior(QueryTrackingBehavior.TrackAll);
    }
    else
    {
        // 生产环境: 默认无跟踪（性能优先）
        options.UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking);
    }
});

注意事项 ​

1. 导航属性加载 ​

csharp
// ❌ 错误: AsNoTracking 后 Include 可能有问题
var order = await context.Orders
    .AsNoTracking()
    .Include(o => o.Items)
    .FirstOrDefaultAsync(o => o.Id == id);

// 如果 Order 和 OrderItem 都引用同一个 Product
// 会创建两个 Product 实例

// ✅ 正确: 使用 AsNoTrackingWithIdentityResolution
var order = await context.Orders
    .AsNoTrackingWithIdentityResolution()
    .Include(o => o.Items)
    .FirstOrDefaultAsync(o => o.Id == id);

最佳实践 ​

1. API 接口统一使用 AsNoTracking ​

csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private readonly AppDbContext _context;

    public ProductsController(AppDbContext context)
    {
        _context = context;
    }

    [HttpGet]
    public async Task<ActionResult<IEnumerable<ProductDto>>> GetProducts()
    {
        return await _context.Products
            .AsNoTracking() // ✅ 始终添加
            .Select(p => new ProductDto
            {
                Id = p.Id,
                Name = p.Name,
                Price = p.Price
            })
            .ToListAsync();
    }

    [HttpGet("{id}")]
    public async Task<ActionResult<ProductDto>> GetProduct(int id)
    {
        var product = await _context.Products
            .AsNoTracking() // ✅ 始终添加
            .Where(p => p.Id == id)
            .Select(p => new ProductDto
            {
                Id = p.Id,
                Name = p.Name,
                Price = p.Price
            })
            .FirstOrDefaultAsync();

        if (product == null)
            return NotFound();

        return product;
    }
}

2. 读写分离 ​

csharp
public class ProductService
{
    private readonly AppDbContext _readContext;  // 无跟踪
    private readonly AppDbContext _writeContext; // 跟踪

    public ProductService(
        IDbContextFactory<AppDbContext> factory)
    {
        _readContext = factory.CreateDbContext();
        _writeContext = factory.CreateDbContext();
    }

    // 读操作
    public async Task<List<Product>> GetProductsAsync()
    {
        return await _readContext.Products
            .AsNoTracking()
            .ToListAsync();
    }

    // 写操作
    public async Task UpdateProductAsync(Product product)
    {
        _writeContext.Products.Update(product);
        await _writeContext.SaveChangesAsync();
    }
}

3. 缓存配合 ​

csharp
public class CachedProductService
{
    private readonly IMemoryCache _cache;
    private readonly AppDbContext _context;

    public async Task<List<Product>> GetActiveProductsAsync()
    {
        const string cacheKey = "active_products";

        // 尝试从缓存获取
        if (_cache.TryGetValue(cacheKey, out List<Product> products))
        {
            return products;
        }

        // 查询数据库（无跟踪）
        products = await _context.Products
            .AsNoTracking()
            .Where(p => p.IsActive)
            .ToListAsync();

        // 存入缓存（5 分钟）
        _cache.Set(cacheKey, products, TimeSpan.FromMinutes(5));

        return products;
    }
}

4. 批量操作优化 ​

csharp
// ❌ 慢: 跟踪所有实体
for (int i = 0; i < 10000; i++)
{
    var product = await context.Products.FindAsync(i);
    // 处理...
}

// ✅ 快: 无跟踪查询
for (int i = 0; i < 10000; i += 1000)
{
    var products = await context.Products
        .AsNoTracking()
        .Where(p => p.Id >= i && p.Id < i + 1000)
        .ToListAsync();
    
    // 处理...
    
    // 清除跟踪（虽然无跟踪,但好习惯）
    context.ChangeTracker.Clear();
}

📊 性能优化检查清单 ​

使用 AsNoTracking 前确认:

  • [ ] 是否需要修改实体?
  • [ ] 是否只需要读取数据?
  • [ ] 是否是 API 返回数据?
  • [ ] 是否是报表或统计?
  • [ ] 是否是下拉列表选项?
  • [ ] 是否是搜索功能?
  • [ ] 是否是导出功能?

如果以上任一为"是",使用 AsNoTracking()!

💡 小结 ​

核心要点:

  • ✅ AsNoTracking 提升性能 30-50%
  • ✅ 内存占用减少 50-60%
  • ✅ API、报表、搜索等只读场景必用
  • ✅ 需要修改实体时不能用
  • ✅ 可配置全局默认行为
  • ✅ 配合缓存效果更佳

使用原则:

只读查询 → AsNoTracking()
需要修改 → 跟踪查询
不确定 → 默认跟踪,后续优化
