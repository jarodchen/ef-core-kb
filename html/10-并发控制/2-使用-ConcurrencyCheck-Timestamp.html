并发控制基础 ​

什么是并发冲突? ​

并发冲突(Concurrency Conflict) 发生在多个用户同时修改同一条记录时,后提交的更改覆盖了先提交的更改,导致数据丢失。

时间线示例:

时刻 T1: 用户 A 读取产品(价格: $100)
时刻 T2: 用户 B 读取产品(价格: $100)
时刻 T3: 用户 A 修改价格为 $120,保存成功
时刻 T4: 用户 B 修改价格为 $110,保存成功

结果: 用户 A 的修改($120)被用户 B 的修改($110)覆盖!
用户 A 以为价格是 $120,实际是 $110 💥 数据不一致!

解决方案: 乐观并发控制 ​

EF Core 使用乐观并发控制(Optimistic Concurrency Control),假设冲突很少发生,在保存时检测冲突。

csharp
// 核心原理: 检查数据是否被其他人修改
// 如果已修改,抛出 DbUpdateConcurrencyException

try
{
    await context.SaveChangesAsync();
}
catch (DbUpdateConcurrencyException ex)
{
    // 处理冲突: 
    // 1. 刷新数据,让用户重新决定
    // 2. 客户端获胜(强制覆盖)
    // 3. 数据库获胜(放弃修改)
    // 4. 合并变更
}

两种实现方式 ​

方式适用场景优点缺点
ConcurrencyCheck监控特定字段灵活,可选择字段需要手动配置每个字段
Timestamp/RowVersion监控整行简单,自动管理只能有一个时间戳列

ConcurrencyCheck 方式 ​

基本概念 ​

ConcurrencyCheck 特性标记在需要监控的属性上,EF Core 会在 UPDATE/DELETE 时将原始值包含在 WHERE 子句中。

csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    [ConcurrencyCheck]  // ← 监控此字段
    public decimal Price { get; set; }
    
    public string Description { get; set; }  // 不监控
}

sql
-- 没有 ConcurrencyCheck
UPDATE Products SET Price = @p0 WHERE Id = @id;

-- 有 ConcurrencyCheck
UPDATE Products SET Price = @p0 
WHERE Id = @id AND Price = @original_price;  -- ← 检查原始值

-- 如果价格已被其他人修改,WHERE 条件不匹配,影响行数 = 0
-- EF Core 检测到影响行数为 0,抛出 DbUpdateConcurrencyException

完整示例 ​

csharp
public class ProductService
{
    private readonly AppDbContext _context;
    
    public async Task UpdatePriceAsync(int productId, decimal newPrice)
    {
        var product = await _context.Products.FindAsync(productId);
        
        if (product == null)
            throw new NotFoundException($"Product {productId} not found");
        
        // 用户可能需要时间来决策,此时其他用户可能也在修改
        product.Price = newPrice;
        
        try
        {
            await _context.SaveChangesAsync();
            Console.WriteLine("价格更新成功");
        }
        catch (DbUpdateConcurrencyException ex)
        {
            // 获取数据库中的当前值
            var databaseEntry = ex.Entries.First().GetDatabaseValues();
            
            if (databaseEntry == null)
            {
                throw new InvalidOperationException("记录已被删除");
            }
            
            var currentPrice = databaseEntry.GetValue<decimal>("Price");
            
            Console.WriteLine($"并发冲突! 当前价格: ${currentPrice}");
            Console.WriteLine("请刷新页面,查看最新价格后重新编辑");
            
            // 刷新实体的值为数据库中的最新值
            ex.Entries.First().Reload(ReloadMode.StoreWins);
            
            throw;  // 或返回错误信息给前端
        }
    }
}

Timestamp 方式 ​

基本概念 ​

Timestamp/RowVersion 是数据库自动管理的二进制列,每次行数据变更时自动更新。这是推荐的方式。

csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    
    [Timestamp]  // ← 或使用 byte[] RowVersion { get; set; }
    public byte[] RowVersion { get; set; }
}

工作原理 ​

sql
-- SQL Server: rowversion 类型(以前叫 timestamp)
CREATE TABLE Products (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(100),
    Price DECIMAL(18,2),
    RowVersion ROWVERSION NOT NULL  -- 自动管理
);

-- 插入时自动生成
INSERT INTO Products (Name, Price) VALUES ('Laptop', 999.99);
-- RowVersion 自动生成,如: 0x00000000000007D1

-- 更新时自动修改
UPDATE Products SET Price = 1099.99 WHERE Id = 1;
-- RowVersion 自动变为: 0x00000000000007D2

-- 并发检查
UPDATE Products SET Price = @p0 
WHERE Id = @id AND RowVersion = @original_version;

-- 如果 RowVersion 不匹配,影响行数 = 0,抛出异常

完整示例 ​

csharp
public class ProductService
{
    private readonly AppDbContext _context;
    
    public async Task UpdateProductAsync(ProductDto dto, byte[] originalRowVersion)
    {
        var product = await _context.Products.FindAsync(dto.Id);
        
        if (product == null)
            throw new NotFoundException($"Product {dto.Id} not found");
        
        // 设置原始 RowVersion
        _context.Entry(product).OriginalValues["RowVersion"] = originalRowVersion;
        
        // 应用修改
        product.Name = dto.Name;
        product.Price = dto.Price;
        
        try
        {
            await _context.SaveChangesAsync();
            Console.WriteLine("更新成功");
        }
        catch (DbUpdateConcurrencyException)
        {
            Console.WriteLine("并发冲突! 数据已被其他人修改");
            throw;
        }
    }
}

// Minimal API 示例
app.MapPut("/api/products/{id}", async (
    int id, 
    ProductDto dto, 
    [FromHeader(Name = "If-Match")] string ifMatch,  // 从请求头获取 RowVersion
    AppDbContext db) =>
{
    var product = await db.Products.FindAsync(id);
    if (product == null)
        return Results.NotFound();
    
    // 解析 RowVersion
    var originalRowVersion = Convert.FromBase64String(ifMatch);
    db.Entry(product).OriginalValues["RowVersion"] = originalRowVersion;
    
    product.Name = dto.Name;
    product.Price = dto.Price;
    
    try
    {
        await db.SaveChangesAsync();
        return Results.NoContent();
    }
    catch (DbUpdateConcurrencyException)
    {
        return Results.Conflict("数据已被修改,请刷新后重试");
    }
});

// TypeScript 客户端
interface Product {
  id: number;
  name: string;
  price: number;
  rowVersion: string;  // Base64 编码
}

async function updateProduct(product: Product) {
  const response = await fetch(`/api/products/${product.id}`, {
    method: 'PUT',
    headers: {
      'Content-Type': 'application/json',
      'If-Match': product.rowVersion  // 发送 RowVersion
    },
    body: JSON.stringify({
      name: product.name,
      price: product.price
    })
  });
  
  if (response.status === 409) {
    alert('数据已被其他人修改,请刷新页面');
    return null;
  }
  
  return await response.json();
}

两种方式对比 ​

详细对比表 ​

特性ConcurrencyCheckTimestamp/RowVersion
配置复杂度中等(需指定字段)简单(自动管理)
监控范围指定字段整行
数据库支持所有数据库SQL Server/Azure SQL 最佳
性能好(WHERE 条件少)最好(单列比较)
灵活性高(可选择字段)低(固定一列)
可靠性中(可能漏掉字段)高(自动监控所有变更)
推荐程度⭐⭐⭐⭐⭐⭐⭐⭐

.NET 9: 增强的冲突解决 API ​

csharp
// .NET 9 引入更便捷的冲突解决方法
catch (DbUpdateConcurrencyException ex)
{
    foreach (var entry in ex.Entries)
    {
        // 新方法: 直接获取差异
        var changes = entry.GetDatabaseValues();
        var conflicts = entry.GetConflictingProperties();
        
        foreach (var conflict in conflicts)
        {
            Console.WriteLine($"{conflict.PropertyName}:");
            Console.WriteLine($"  Original: {conflict.OriginalValue}");
            Console.WriteLine($"  Current:  {conflict.CurrentValue}");
            Console.WriteLine($"  Database: {conflict.DatabaseValue}");
        }
        
        // 新方法: 智能合并
        entry.ResolveConflicts(ConflictResolution.ClientWins);
        // 或
        entry.ResolveConflicts(ConflictResolution.StoreWins);
        // 或
        entry.ResolveConflicts(ConflictResolution.Merge);  // .NET 9 新增
    }
    
    await context.SaveChangesAsync();
}

2. 始终处理并发异常 ​

csharp
// ✅ 推荐: 完整的异常处理
public async Task UpdateAsync(Entity entity)
{
    try
    {
        await _context.SaveChangesAsync();
    }
    catch (DbUpdateConcurrencyException ex)
    {
        _logger.LogWarning(ex, "并发冲突 detected for {EntityType}", 
            ex.Entries.First().Entity.GetType().Name);
        
        // 根据业务逻辑选择策略
        await HandleConcurrencyConflictAsync(ex);
    }
}

private async Task HandleConcurrencyConflictAsync(DbUpdateConcurrencyException ex)
{
    // 策略 1: 刷新并重试
    foreach (var entry in ex.Entries)
    {
        entry.Reload();
    }
    await _context.SaveChangesAsync();
    
    // 策略 2: 返回冲突信息给用户
    // throw new ConcurrencyConflictException("数据已被修改");
}

常见陷阱 ​

陷阱 1: 忘记设置原始值 ​

csharp
// ❌ 错误: 未设置原始 RowVersion
var product = await _context.Products.FindAsync(1);
product.Price = 120;
await _context.SaveChangesAsync();  // 💥 不会检测并发冲突!

// ✅ 正确: 设置原始值
var product = await _context.Products.AsNoTracking().FirstOrDefaultAsync(p => p.Id == 1);
_context.Entry(product).State = EntityState.Modified;
_context.Entry(product).OriginalValues["RowVersion"] = originalRowVersion;
product.Price = 120;
await _context.SaveChangesAsync();  // ✅ 会检测冲突

csharp
// ⚠️ 注意: ExecuteUpdateAsync 不检查并发

}

总结 ​

核心要点 ​

  1. 并发控制: 检测并防止多人同时修改导致的数据丢失
  2. ConcurrencyCheck: 监控特定字段,灵活但需手动配置
  3. Timestamp: 监控整行,自动管理,推荐使用
  4. 异常处理: 捕获 DbUpdateConcurrencyException 并适当处理
  5. API 设计: 使用 ETag/If-Match 头部传递 RowVersion

场景推荐方式原因

代码模板 ​

csharp
// 模板 1: Timestamp 实体
public class BaseEntity
{
    public int Id { get; set; }
    public byte[] RowVersion { get; set; }
}

// 模板 2: 并发更新
try
{
    _context.Entry(entity).OriginalValues["RowVersion"] = originalVersion;
    // 应用修改...
    await _context.SaveChangesAsync();
}
catch (DbUpdateConcurrencyException)
{
    // 处理冲突
    await HandleConflictAsync();
}

// 模板 3: API ETag
app.MapGet("/api/entities/{id}", async (int id, DbContext db) =>
{
    var entity = await db.Entities.FindAsync(id);
    var etag = Convert.ToBase64String(entity.RowVersion);
    return Results.Ok(entity).WithETag(etag);
});
