什么是查询评估 ​

概念理解 ​

查询评估(Query Evaluation) 是 EF Core 决定 LINQ 查询的哪部分转换为 SQL(服务端执行),哪部分在 C# 中执行(客户端执行)的过程。

csharp
var products = context.Products
    .Where(p => p.Price > 100)              // ← 服务端评估(SQL)
    .OrderBy(p => p.Name)                   // ← 服务端评估(SQL)
    .Select(p => new {                      // ← 服务端评估(SQL)
        p.Id,
        p.Name,
        FormattedPrice = FormatPrice(p.Price)  // ← ??? 
    })
    .ToList();

.NET Core 3.0+ 的变更 ​

重大Breaking Change ​

csharp
// .NET Core 2.x: 允许隐式客户端评估
var products = context.Products
    .Where(p => p.Price > 100)
    .Select(p => new {
        p.Name,
        FormattedPrice = FormatPrice(p.Price)  // ⚠️ 警告: 客户端评估
    })
    .ToList();

// 行为:
// 1. WHERE 子句在数据库执行
// 2. 加载所有匹配记录到内存
// 3. FormatPrice() 在客户端执行
// 💥 性能问题: 可能加载大量数据!

// .NET Core 3.0+: 默认禁止隐式客户端评估
var products = context.Products
    .Where(p => p.Price > 100)
    .Select(p => new {
        p.Name,
        FormattedPrice = FormatPrice(p.Price)  // 💥 InvalidOperationException!
    })
    .ToList();

// 错误信息:
// The LINQ expression 'FormatPrice(p.Price)' could not be translated. 
// Either rewrite the query in a form that can be translated, or switch to 
// client evaluation explicitly by inserting a call to 'AsEnumerable()', 
// 'AsAsyncEnumerable()', 'ToList()', or 'ToListAsync()'.

原因: 隐式客户端评估导致严重的性能问题

何时使用客户端评估 ​

✅ 适合客户端评估:

  • 复杂的 C# 逻辑(无法转换为 SQL)
  • 调用外部 API 或服务
  • 格式化显示数据
  • 业务规则验证

❌ 不适合客户端评估:

  • 过滤条件(应在数据库执行)
  • 排序(应在数据库执行)
  • 分页(应在数据库执行)
  • 聚合(应在数据库执行)

示例: 混合法 ​

csharp
public class ProductService
{
    private readonly AppDbContext _context;
    private readonly IPricingService _pricingService;  // 外部服务
    
    public async Task<List<ProductDto>> GetProductsWithPricingAsync()
    {
        // 步骤 1: 服务端过滤和投影(减少数据量)
        var products = await _context.Products
            .Where(p => p.IsActive && p.Stock > 0)
            .Select(p => new {
                p.Id,
                p.Name,
                p.BasePrice,
                p.CategoryId
            })
            .ToListAsync();
        
        // 步骤 2: 客户端处理(调用外部服务)
        var result = products.Select(p => new ProductDto
        {
            Id = p.Id,
            Name = p.Name,
            BasePrice = p.BasePrice,
            // 调用外部定价服务(无法在 SQL 中执行)
            FinalPrice = _pricingService.CalculatePrice(p.Id, p.BasePrice),
            // 复杂业务逻辑
            Availability = GetAvailabilityText(p.Stock, p.CategoryId)
        }).ToList();
        
        return result;
    }
    
    private string GetAvailabilityText(int stock, int categoryId)
    {
        // 复杂业务规则,无法转换为 SQL
        if (stock == 0) return "Out of Stock";
        if (stock < 10) return "Low Stock";
        if (categoryId == 1) return "In Stock (Fast Moving)";
        return "In Stock";
    }
}

混合评估问题 ​

问题 1: 意外加载大量数据 ​

csharp
// ❌ 危险: 忘记先过滤

总结 ​

核心要点 ​

  1. 服务端评估: 转换为 SQL,在数据库执行(高效)
  2. 客户端评估: 在 C# 中执行(.NET Core 3.0+ 需显式声明)
  3. 最佳实践: 最大化服务端评估,明确切换点
  4. 性能影响: 客户端评估可能加载大量数据
  5. 监控: 启用日志检测意外的客户端评估

评估决策流程 ​

LINQ 查询操作
├─ 能转换为 SQL?
│   ├─ 是 → 服务端评估 ✅
│   └─ 否 → 需要客户端评估
│       ├─ 可以先过滤?
│       │   ├─ 是 → 先 Where/Take,再 AsEnumerable()

性能对比 ​

场景: 100万条记录,需要100条

方式              | 数据传输 | 内存占用 | 耗时
-----------------|----------|----------|------
完全服务端       | 100条    | 低       | 50ms
意外客户端评估   | 100万条  | 高       | 5000ms
显式客户端评估   | 1000条*  | 中       | 200ms

* 先过滤后的数据量

代码模板 ​

csharp
// 模板 1: 完全服务端评估
var result = await context.Entities
    .Where(e => e.Condition)
    .OrderBy(e => e.Field)
    .Skip(skip).Take(take)
    .Select(e => new Dto { ... })
    .ToListAsync();

// 模板 2: 混合评估
var data = await context.Entities
    .Where(e => e.Filter)      // 服务端
    .ToListAsync();             // 执行查询

var result = data.Select(e => new Dto
{
    Field = ComplexMethod(e)   // 客户端
}).ToList();

// 模板 3: 明确切换点
var result = context.Entities
    .Where(e => e.Filter)      // 服务端
    .AsEnumerable()            // 明确切换
    .Select(e => new Dto
    {
        Field = ComplexMethod(e)  // 客户端
    })
    .ToList();
