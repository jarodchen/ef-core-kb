可视化建模工具(Entity Developer) ​

概述 ​

Entity Developer 是一款强大的可视化 EF Core 建模工具,支持从数据库生成实体模型、设计 ER 图、自定义代码生成模板等。相比命令行逆向工程,它提供更直观的图形界面和更灵活的配置选项。

官方网站: https://www.devart.com/entitydeveloper/
价格: 商业软件(提供免费试用)

核心功能 ​

1. 可视化 ER 图设计 ​

  • ✅ 拖拽式表关系设计
  • ✅ 自动生成外键约束
  • ✅ 实时验证模型完整性
  • ✅ 导出为图片/PDF

2. 双向同步 ​

  • Database First: 从数据库生成模型
  • Model First: 从模型生成数据库
  • Code First: 生成 C# 代码

3. 多 ORM 支持 ​

  • EF Core (所有版本)
  • Entity Framework 6
  • LINQ to SQL
  • NHibernate

4. 代码生成模板 ​

  • T4 模板引擎
  • 自定义代码风格
  • 支持部分类扩展

DbContext ​

public partial class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }
    
    public virtual DbSet<User> Users { get; set; }
    public virtual DbSet<Product> Products { get; set; }
    public virtual DbSet<Order> Orders { get; set; }
    
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.ApplyConfiguration(new UserConfiguration());
        modelBuilder.ApplyConfiguration(new ProductConfiguration());
        modelBuilder.ApplyConfiguration(new OrderConfiguration());
        
        base.OnModelCreating(modelBuilder);
    }
}

Fluent API 配置 ​

csharp
public class UserConfiguration : IEntityTypeConfiguration<User>
{
    public void Configure(EntityTypeBuilder<User> builder)
    {
        builder.ToTable("Users");
        
        builder.HasKey(u => u.Id);
        
        builder.Property(u => u.UserName)
            .IsRequired()
            .HasMaxLength(100);
        
        builder.Property(u => u.Email)
            .IsRequired()
            .HasMaxLength(200);
        
        builder.HasIndex(u => u.Email).IsUnique();
        
        builder.HasMany(u => u.Orders)
            .WithOne(o => o.User)
            .HasForeignKey(o => o.UserId);
    }
}

实际应用场景 ​

场景 1: 大型遗留数据库 ​

挑战: 200+ 表,复杂关系,命名不规范

解决方案:

  1. 使用 Entity Developer 逆向工程
  2. 可视化调整实体命名
  3. 配置复杂关系映射
  4. 生成标准化代码

效果:

  • ⏱️ 节省 80% 手工编码时间
  • ✅ 统一命名规范
  • 📊 清晰的 ER 文档

场景 2: 团队协作开发 ​

挑战: 多人修改数据库,模型同步困难

解决方案:

  1. 共享 .edml 模型文件
  2. 定期从生产库更新模型
  3. 代码生成模板统一
  4. 版本控制集成

效果:

  • 🤝 团队模型一致
  • 🔄 自动化同步
  • 📝 变更可追溯

场景 3: 多租户架构 ​

挑战: 每个租户独立 Schema,需要动态切换

解决方案:

  1. 设计通用模型
  2. 自定义模板添加 TenantId
  3. 配置 Schema 切换逻辑
  4. 生成多租户感知代码

生成代码:

csharp
public class MultiTenantDbContext : DbContext
{
    private readonly string _tenantSchema;
    
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        foreach (var entityType in modelBuilder.Model.GetEntityTypes())
        {
            entityType.SetSchema(_tenantSchema);
        }
        
        base.OnModelCreating(modelBuilder);
    }
}

替代方案 ​

免费工具 ​

1. EF Core Power Tools ​

优点:

  • ✅ 完全免费
  • ✅ 开源
  • ✅ 持续更新

缺点:

  • ⚠️ 无可视化设计器
  • ⚠️ 代码生成不可定制

适用: 小型项目,预算有限

2. Visual Studio Designer (EF6) ​

优点:

  • ✅ 内置于 VS
  • ✅ 简单易用

缺点:

  • ❌ 不支持 EF Core
  • ❌ 功能有限

适用: 传统 EF6 项目

商业工具 ​

1. Entity Developer (DevArt) ⭐⭐⭐⭐⭐ ​

价格: $299/开发者
优势: 功能最全面,支持多 ORM

2. LLBLGen Pro ​

价格: $499/开发者
优势: 强大的代码生成引擎

总结 ​

何时使用 Entity Developer? ​

✅ 推荐使用:

  • 大型复杂数据库(50+ 表)
  • 需要定制化代码生成
  • 团队协作开发
  • 遗留系统现代化改造
  • 需要可视化 ER 文档

❌ 不推荐:

  • 小型简单项目(< 10 表)
  • 预算有限(使用免费的 EF Core Power Tools)
  • 纯 Code First 工作流
  • 不需要可视化设计

投资回报 ​

时间节省:

  • 手工编码: 200 表 × 30分钟 = 100 小时
  • Entity Developer: 10 小时
  • 节省: 90 小时 ≈ 11 个工作日

质量提升:

  • ✅ 统一命名规范
  • ✅ 减少人为错误
  • ✅ 完整文档

结论: 对于中型以上项目,ROI 极高! 🚀
